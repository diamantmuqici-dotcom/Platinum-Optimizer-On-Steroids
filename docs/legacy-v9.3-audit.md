# Platinum+ Optimizer V9.3 — source audit and migration decision

## Scope and method

The complete 2,841-line V9.3 batch file was read before changes. Its original bytes are preserved as **plain text only** at [`../legacy/Platinum+Optimizer.V9.3.FREE.cmd.disabled.txt`](../legacy/Platinum+Optimizer.V9.3.FREE.cmd.disabled.txt); it is not invoked by the new launcher. The repository's original `.cmd` path is now a small compatibility frontend for the new PowerShell application.

A static, non-executing extractor at [`../tools/audit_legacy.py`](../tools/audit_legacy.py) expands the large generated service and AppX loops, inventories command-level writes/removals, records line numbers, detects exact repeated effects, and emits [`legacy-v9.3-tweak-inventory.csv`](legacy-v9.3-tweak-inventory.csv) plus [`legacy-v9.3-audit-summary.json`](legacy-v9.3-audit-summary.json). Regenerate both with:

```sh
python tools/audit_legacy.py
```

The inventory contains **1,687 effect rows**, each with a unique effect ID and a source-line reference. It includes **1,214 effects parsed from explicit `reg` commands** plus **104 registry startup changes expanded from a generated service loop** (1,318 total registry mutation effects), alongside generated Service Control Manager actions and cleanup, boot, power, task, package, logging, and application operations. There are **267 rows that repeat an identical target/setting/value effect**. These are static extraction counts, not distinct settings or a live machine's final state. The CSV records the purpose/category, Windows support status, defaults/current values, expected benefit, risk, admin/reboot/vendor dependencies, migration decision, rollback, and rationale for each extracted effect.

This is a **source audit, not a claim about an unknown PC's live registry**. V9.3 did not capture old values before overwriting them. As a result, the prior runtime value, OEM policy, driver interpretation, and actual rollback state cannot be reconstructed from source. The CSV intentionally marks those facts as unknown rather than inventing defaults. Windows 10/11 support is also marked unknown where V9.3 did not check a build or capability.

## Executive decision

**No V9.3 system mutation is retained for automatic execution.** This is not because every legacy setting is necessarily harmful on every PC; it is because the file applies broad undocumented or unverified settings without per-setting capability checks, exact state capture, verification, rollback, or controlled measurements. Keeping a questionable command in the default path would contradict the requested safety and reversibility goals.

The following *ideas* are retained with safer implementations:

- CPU, GPU, memory, storage, board, BIOS, display, Windows, and power-source detection: replaced with read-only Windows CIM/WMI discovery; unsupported fields remain `Unknown`.
- Backups: replaced with timestamped local snapshots, manifest checksums, a recorded change ledger, and section-scoped restore. The new engine does not claim that a System Restore point or a whole-registry export can roll back every setting.
- Power profiles: now select only an already-installed built-in plan, after preview; the previous active plan is recorded and can be restored.
- Game Mode, capture, Windows Graphics, mouse, and startup: the app links to Windows Settings rather than writing undocumented policy/driver values.
- Network testing: explicit ICMP measurements and an optional per-adapter IPv4 DNS selection use Windows' DnsClient cmdlet, are backed up, verified, and rolled back on failure.
- Game list, app inventory, service audit, BCD view, and startup view: read-only; no process injection or bulk disable/remove.

## High-risk and unsupported examples

- `FeatureSettingsOverride` / `FeatureSettingsOverrideMask`: security-mitigation-sensitive and CPU/build-dependent; the old file sets these more than once. The new app does not write them.
- `DisableMemoryCompression`, `DisableMemoryScrubbing`, `DisableWorkingSetAging`, `LargePageAlways`, pagefile, pool, cache, and NUMA values: no verified universal gaming benefit; many are not documented user configuration interfaces.
- `DisableWriteCacheBufferFlush`, arbitrary NVMe queue/timeout and disk registry values: data-integrity, driver, or performance risk.
- `TdrDelay`, `TdrDdiDelay`, `TdrLevel`, `HwSchMode`, DWM/Direct3D/GPU scheduler/queue settings: build/driver/game dependent; forcing them globally is not a substitute for supported Windows Graphics settings.
- `CoolBits`, `RMForceMaxPerf`, Intel `EnableOverclock`, Intel thermal-throttle overrides, AMD crash-defender service changes: vendor-specific and potentially unsafe; no vendor profile is written by the replacement.
- `sc config` plus direct `Services\<name>\Start` registry writes: duplicate mechanisms can conflict, trigger starts/dependencies are not preserved, and current state is never read.
- `wevtutil cl Security`, disabling Defender/WER/System diagnostics, UAC/VBS/HVCI changes, and OneDrive profile deletion: destructive or security-reducing.
- Windows Update lockdown deletes servicing content, pauses through 2099, disables update tasks/services, and edits service ACLs. The new app never disables Windows Update.

## Duplicate and contradiction notes

The inventory's duplicate count is based on identical extracted operation/target/setting/value tuples. In addition, V9.3 contains semantic conflicts that do not appear as exact duplicates: for example, GPU flip/overlay values are set more than once with different values; memory-management flags are repeatedly written and later deleted; visual-effects settings are set to different values; services are disabled in one list and later set back to demand/automatic; Store and Windows Update code paths partially undo earlier writes. This makes the final state ordering-dependent and prevents a truthful single "recommended value" from being stated.

## Migration plan implemented

1. Preserve the source only as a non-runnable audit artifact; replace its launch path with a transparent local frontend.
2. Remove every V9.3 write, destructive command, forced reboot, service loop, package removal, and security/network/driver override from the executable path.
3. Detect Windows/hardware first with read-only CIM/WMI; never infer unknown model/build fields.
4. Offer profiles that select an existing power plan only after a preview and battery/compatibility check; perform backup, apply, verify, and failure rollback.
5. Offer an optional supported DNS action with a per-adapter snapshot, explicit confirmation, verification, and automatic rollback on error.
6. Keep Game Mode/capture/graphics/mouse/startup decisions in Windows Settings; service, BCD, AppX, startup, task, and driver audits remain read-only.
7. Capture before/after system counters and ping only on user request; explicitly report missing game FPS/frame-time/DPC latency as **Not measured**.
8. Test pure compatibility, plan-selection, backup schema, dry-run semantics, and audit coverage without running the legacy code.
